ACT4: components, workflow and examples

riscv-arch-test, branch act4, commit aadb7424a. Each claim carries an evidence tag: run means I observed it in a run, code means I read it in the source, and inferred means I deduced it from the code but did not observe it.

Summary

  1. ACT4 produces self-checking ELFs. A test file is built twice. The first build runs on Sail, the reference model, and dumps a signature. ACT then embeds that signature as expected values in a second build. The DUT (the device under test) runs the second ELF, which compares each result at run time and prints RVCP-SUMMARY: TEST PASSED or TEST FAILED. run
  2. It has four stages, each with one owner.
    • Generate: make tests runs testgen and covergroupgen.
    • Select and build: the act program does both.
    • Run: run_tests.py.
    • Measure coverage: act --coverage with Questa or VCS.
  3. Python never computes expected values. The generators emit only input operands and check sites (RVTEST_SIGUPD). Sail supplies every expected value at build time. code
  4. A DUT configuration is one directory. It holds test_config.yaml, a UDB configuration, rvmodel_macros.h, link.ld, sail.json and, optionally, run_cmd.txt. Test selection matches the test header against the extensions that UDB lists for that configuration.
  5. The minimal case is verified end to end. The I suite on sail-rv64-max selects 51 tests and runs 255 build tasks in 45 s, and all tests pass. A corrupted expected value makes the test fail, and the failure output names the testcase, the register, the bad value and the expected value. run
  6. Five behaviours matter for new work. Section 15 lists them all.
    • The generation stamps ignore EXTENSIONS. run
    • V and most privileged tests are not checked in. code
    • act --keep-going is not reachable from make. code
    • UDB fails on this cluster's NFS home unless its cache directory is moved. run
    • The Questa and VCS coverage step could not run here, because no simulator is installed. not run
Orientation

1Terms and verbs

This report uses each term below with exactly one meaning. Most nouns are the project's own words from AGENTS.md.

Testplan
One CSV file, testplans/<suite>.csv. Each row is an instruction; each column after the fixed columns is a coverpoint.
Coverpoint
A named property to exercise, for example cp_rd (every destination register) or cr_rs1_rs2_edges (a cross of edge values).
Bin
One value of a coverpoint, for example b5 for rd = x5.
Testcase
The code that hits one bin. It loads the operands, executes one instruction under a label and makes one check.
TestChunk
An unsplittable group of testcases. File splitting never cuts a TestChunk.
Test file
One .S (or .c) file, for example tests/rv64i/I/I-add-00.S.
Test suite
One extension directory, for example tests/rv64i/I/. EXTENSIONS filters on these directory names.
Test header
Strict YAML between START_TEST_CONFIG and END_TEST_CONFIG in each test file.
DUT configuration
A directory under config/ that describes one device under test (DUT).
Reference model
Sail (sail_riscv_sim), version 0.16 exactly. It is the only supported model.
Signature
The memory region between begin_signature and end_signature. Sail writes it out as .sig.
Expected-results file
.results: the signature rewritten as .quad/.word directives, then included into the self-checking ELF.
Signature ELF
build/<rel>.sig.elf: built without RVTEST_SELFCHECK. Each check stores its result.
Self-checking ELF
elfs/<rel>.elf: built with RVTEST_SELFCHECK. Each check compares its result with the expected value. This is the deliverable.
Build task
One node of the build graph that act executes. Build counters such as "255 succeeded" count build tasks, not tests.

The verbs name pipeline stages. They are not used for anything else:

Verb Meaning Owner
generate Write test files and covergroups from testplans. testgen, covergroupgen (via make tests)
select Choose the test files that apply to one DUT configuration. act (select_tests.py)
build Compile the signature ELF, run the reference model, convert the signature, compile the self-checking ELF. act (build_plan.py, build.py)
run Execute self-checking ELFs on the DUT. run_tests.py
check Compare a result with its expected value, inside the ELF, at run time. RVTEST_SIGUPD and the other framework macros
report Classify each run as pass or fail and write summary.log. run_tests.py
measure coverage Replay Sail traces into SystemVerilog covergroups. act --coverage with Questa or VCS

2Objective and scope

ACT4 generates RISC-V architectural certification tests and builds self-checking ELFs whose expected values come from the reference model (AGENTS.md). The objective is to confirm that a DUT implements the selected ISA extensions with the architecturally required results. It is not a performance test or a microarchitectural stress test.

Specification requirement

The architectural result of each instruction, as defined by the RISC-V ISA specification. Sail is the executable form of that specification, so Sail's result is the expected value.

Project convention
  • One testcase per coverpoint bin.
  • Tests are generated, and the generated files are checked in.
  • Checks happen inside the ELF, not by comparing signature files afterwards.
  • Functional coverage is measured separately with SystemVerilog covergroups.

The Python workspace has three packages (pyproject.toml):

5The act program

The entry point is act.act:main, a Typer command run_act framework/src/act/act.py:31-212. Its control flow:

  1. Validate options. --verbose implies --debug and one job. --debug cannot be combined with --fast or --clean-intermediates. --certificate must name a known certificate framework/src/act/act.py:85-110.
  2. Parse test headers. generate_test_dict(test_dir, extensions, exclude) reads every selected test file's YAML header. A malformed header stops the run framework/src/act/parse_test_constraints.py:179-221.
  3. Prepare each DUT configuration. This step loads test_config.yaml into a frozen Config and checks the tool versions: Sail exactly 0.16, GCC ≥ 15, Clang ≥ 20 framework/src/act/config.py:127-172. It then runs the UDB tasks: validate the configuration, write the C and SV headers, list the extensions framework/src/act/parse_udb_config.py:119-194.
  4. Select tests. select_tests filters by harts, privilege, experimental status, extensions and parameters, then writes work/<cfg>/test_list.md framework/src/act/select_tests.py:101-233.
  5. Plan the build. generate_build_plan emits BuildTask nodes for every selected test, plus coverage tasks if requested framework/src/act/build_plan.py:567-693.
  6. Execute. build.build() runs the graph on a thread pool with a content-hash cache, then prints N succeeded, N up-to-date, N failed. Any failure exits with status 1 framework/src/act/act.py:168-195.

Consistency rule

The UDB configuration, sail.json, the linker script and the DUT's real behaviour must agree. UDB decides which tests are selected. Sail decides the expected values. The DUT is checked against both. A mismatch between UDB and Sail produces a test that is wrong for that DUT, not a DUT bug.

From testcase to assembly

A coverpoint generator iterates over its bins. For each bin, it:

  1. reserves registers through TestData.int_regs;
  2. draws random operands for the parameters it does not fix (the RNG seed is a hash of instruction plus coverpoint, so output is reproducible);
  3. calls the formatter.

The formatter returns three lists of lines generators/testgen/src/testgen/formatters/types/r_type.py:19-36:

  • setup: RVTEST_TESTDATA_LOAD_INT for each operand;
  • test: the instruction under test;
  • check: RVTEST_SIGUPD.

The label <covergroup>_<coverpoint>_<bin> links the testcase to its covergroup. An example is I_add_cg_cp_rs1_b0. Each label also has a debug string, which the failure reporter prints. 

##### START_TEST_CONFIG #####
# REQUIRED_EXTENSIONS: ['I']
# params:
#   MXLEN: 64
# MARCH: rv64i_zicsr_zifencei
##### END_TEST_CONFIG #####
#define SIGUPD_COUNT 594
#include "riscv_arch_test.h"
RVTEST_BEGIN
# Testcase cp_rs1 (Test source rs1 = x0)
  RVTEST_TESTDATA_LOAD_INT(x3, x0)  # load rs1: x0 = 0xab8f14e2795ba545
  RVTEST_TESTDATA_LOAD_INT(x3, x11) # load rs2: x11 = 0x7cff6728488620d9
I_add_cg_cp_rs1_b0:
  add x28, x0, x11                  # perform operation
  RVTEST_SIGUPD(x2, x5, x4, x28, I_add_cg_cp_rs1_b0, I_add_cg_cp_rs1_b0_str)

Rules visible in this excerpt:

  • Reserved registers. x2 is the signature pointer, x3 the data pointer, x4 the temporary register and x5 the link register generators/testgen/src/testgen/data/registers.py:103-118. When a testcase needs one of them, the allocator moves the pointer with mv and restores it afterwards.
  • SIGUPD_COUNT is the number of checks plus a margin of 10 generators/testgen/src/testgen/io/writer.py:20-82.
  • File splitting. A new file starts when the next TestChunk would exceed 1000 testcases, or 512 for privileged files generators/testgen/src/testgen/constants.py:31-32.
  • File names are <suite>-<instr>-NN.S.
  • Variants. testgen writes rv32 and rv64 variants of each suite, and E-base variants for the suites listed in E_EXTENSION_TESTS. With EXTENSIONS=I, it therefore writes four suites: rv32i/I, rv64i/I, rv32e/E and rv64e/E run.
Project convention

Generated test files and covergroups are checked in, and CI checks that they match their generators. Exceptions: .gitignore excludes the vector suites (tests/rv{32,64}i/V*, Zv*) and all privileged suites except PMP* and *Sv* .gitignore:31-40. For those suites, the generator output exists only after make tests.

covergroupgen

For each instruction, covergroupgen builds one covergroup:

  1. It opens the covergroup with templates/instruction.sv.
  2. It appends one template per coverpoint column, with @INSTR@, @ARCH@ and related placeholders substituted.
  3. It closes with endgroup.sv.

It also writes <arch>_sample(), a case on the instruction name generators/coverage/src/covergroupgen/generate.py:608-870. The result for add is covergroup I_add_cg in coverpoints/unpriv/I_coverage.svh.

8Select

select_tests applies the stages in Figure 4 in order framework/src/act/select_tests.py:101-133. The extension check does not read implemented_extensions from the YAML directly. It reads extensions.txt, which udb list extensions produces. That list includes the extensions implied by the ones the YAML names: 142 entries for sail-rv64-max run. The parameter check compares the header's params with the UDB params. A string value with an operator, such as '>=64', is compared numerically framework/src/act/select_tests.py:32-61. The header parameter MXLEN is what separates the rv32i/ and rv64i/ copies of a suite.

Test header schema

Allowed keys: REQUIRED_EXTENSIONS (strings, or lists of alternatives), FORBIDDEN_EXTENSIONS, MARCH (it must match rv(32|64|${XLEN})[ieg].*), NEEDS_SIGNATURE (default true), MIN_HARTS (default 1) and params. Any other key fails validation framework/src/act/parse_test_constraints.py:45-56. No checked-in test uses FORBIDDEN_EXTENSIONS, NEEDS_SIGNATURE, MIN_HARTS or alternative lists. code

Cache

The cache never uses file modification times. A build task is up to date when two conditions hold framework/src/act/build_cache.py:71-187:

  1. All its outputs exist.
  2. Its recipe hash equals the hash stored in .act_build_cache.json. The recipe hash combines the SHA-256 of each input file, the command, and the recipe hashes of its dependencies.

Example B shows the effect: after an unchanged rebuild with DEBUG=True, 51 build tasks were reported as "up-to-date" run.

Parallelism and failure

All build tasks for all configurations go into one build() call. The executor is a ThreadPoolExecutor(max_workers=jobs) and runs each subprocess in its own process group framework/src/act/build.py:106-384. On the first failure, without keep_going, the executor:

  1. sends SIGKILL to every active process group;
  2. cancels the queued tasks;
  3. prints the failed command after a "Reproduce with" header.

Each build task times out after 300 s by default.

10Check (self-checking)

RVTEST_SIGUPD has two expansions, selected by RVTEST_SELFCHECK tests/env/signature.h:20-44: 

LREG  _TEMP_REG, 0(_SIG_PTR)          # expected value from .results
beq   _TEMP_REG, _R, 1f
jal   _LINK_REG, failedtest_<link>_<temp>
RVTEST_WORD_PTR _INST_PTR ; RVTEST_WORD_PTR _STR_PTR
1: addi _SIG_PTR, _SIG_PTR, SIG_STRIDE

The signature expansion stores _R instead (SREG _R, 0(_SIG_PTR)). It branches over a failure jump of the same size, so both ELFs have the same code addresses. This is required: the signature records program counters and data addresses, and the self-checking ELF compares against them.

The address identity depends on three things:

  • LA() and LI() have a fixed length tests/env/utils.h:296-433.
  • The pass strings successstr and SIGRUN have the same length.
  • .text.rvmodel is placed after .data, because DUT code in rvmodel_macros.h may differ from the Sail versions in sail_macros.h.

Besides the per-testcase compare, the framework checks four things at run time:

  1. Canary. The first signature word must equal the canary value tests/env/rvtest_setup.h:1694-1733.
  2. Signature pointer. At the end, sigptr − signature_base must equal the stored final_sig_offset. This catches skipped or extra checks tests/env/rvtest_setup.h:116-157.
  3. Trap-signature size must match the recorded size. Only when STANDARD_SM_SUPPORTED is defined.
  4. Abort marker. The value 0xBAD0DEAD must not appear. Only when STANDARD_SM_SUPPORTED is defined.

Unprivileged tests do not run in M-mode. rvmodel_boot drops to U-mode (or S-mode) unless the test defines BOOT_TO_MMODE. In Example E, the trace shows add retiring in mode [U]. run

T-SBI

Privileged tests use T-SBI, the framework's minimal trap-based service interface, through ecall: a0 holds the operation code, a1 an optional argument, and the result comes back in a0. The operations are mode changes (TSBI_GOTO_{M,S,U,VS,VU}MODE), CSR access and physical loads and stores. T-SBI avoids a6 and a7 so that it works on RV32E tests/env/rvtest_trap_handler.h:1-120.

11Run and report

run_tests.py "<run_cmd>" <elf_dir> runs every ELF under elf_dir in a process pool run_tests.py:238-336. For each ELF it:

  1. expands {debug:…}, __TRACEFILE__ and __SUMMARYFILE__;
  2. appends the ELF path to the command;
  3. runs the command with a 300 s timeout.

A test passes only if all three hold:

  • The output contains RVCP-SUMMARY: TEST PASSED.
  • The exit code is 0.
  • No FAILED or SIGRUN line appears.

A mismatch between the summary line and the exit code gets its own message. For example, "TEST FAILED but exit code 0" points at a broken RVMODEL_HALT_FAIL run_tests.py:186-232. SIGRUN means that a signature ELF ran on the DUT instead of a self-checking ELF. 

rv64i/I/I-add-00.log    RVCP-SUMMARY: TEST PASSED - Test File "I-add-00.S"
rv64i/I/I-addi-00.log   RVCP-SUMMARY: TEST PASSED - Test File "I-addi-00.S"
rv64i/I/I-addiw-00.log  RVCP-SUMMARY: TEST PASSED - Test File "I-addiw-00.S"

12Measure coverage

make coverage adds three build tasks per test framework/src/act/build_plan.py:325-399:

  1. Sail re-runs the self-checking ELF with --trace.
  2. sailLog2Trace converts the trace to text RVVI (ORDER … PC … INSN … MODE … X n value).
  3. A symlink to the objdump.

For each coverage group, meaning each test directory such as rv64i/I, ACT writes a tracelist. It compiles fcov/testbench.sv with <SUITE>_COVERAGE defined, using Questa (vsim -do riscv-arch-test.do) or VCS (riscv-arch-test-vcs.sh). The testbench replays the traces into the generated covergroups framework/src/act/build_plan.py:402-557. Reports go to work/<cfg>/reports/, and _overall_summary.txt ends with RVCP COVERAGE COMPLETE or INCOMPLETE.

Limitation

Coverage requires Sail as the reference model. sail_to_rvvi.py does not parse traps or interrupts yet framework/src/act/sail_to_rvvi.py:44. code

14Debug and triage

  1. Read work/<cfg>/summary.log, then the failing logs/<rel>.log. The Test Info line names the bin.
  2. Rebuild with DEBUG=True EXTENSIONS=<suite> to get the objdump of the signature ELF, the Sail trace and the trap report.
  3. Find the label (for example I_add_cg_cp_rs1_b1) in .sig.elf.objdump and .sig.trace. Compare what Sail did with what the DUT did.
  4. Check the configuration before the DUT. Check UDB against the DUT, then sail.json against the DUT. A configuration mismatch looks exactly like a DUT bug.
  5. For a build failure, act prints the command after a "Reproduce with" header. Run it by hand.

16Extension points

A new unprivileged extension needs the pieces below. Report 2 applies this list to the Integrated Matrix Extension.

Piece Location Note
Testplan testplans/<Suite>.csv The suite name, split at capital letters, becomes REQUIRED_EXTENSIONS. A name starting with V or Zv turns on vector mode.
Instruction formatter formatters/types/*_type.py InstructionTypeConfig, optionally with VectorTypeConfig.
Coverpoint generators coverpoints/*.py Reuse existing ones through prefix match, or add new ones.
Covergroup templates covergroupgen/templates/*.sv sample_<TYPE>.sv plus one template per new coverpoint.
Check macro tests/env/signature.h Needed only for state outside the existing integer, FP and vector registers. The signature and self-checking expansions must have the same size.
UDB extension The UDB gems, or UDB_LOCAL_PATH Needed for extensions.txt and the <EXT>_SUPPORTED macros.
Reference model Sail 0.16 and sail.json Sail must implement the instructions. The version check requires exactly 0.16.
Toolchain compiler_exe The assembler must accept the MARCH string, or the tests must encode instructions as .insn or .word.
Coverage decoder fcov/disassemble.svh, RISCV_imported_decode_pkg.svh (generated from riscv-opcodes) Needed only for coverage.
